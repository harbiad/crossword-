# 13×13 English-answer template feasibility

Dictionary: frozen Batch006 QA. Production remains compatibility mode. No CEFR,
translation, approval, inversion, uniqueness, clue, or validator changes.

## Scope and reproducibility

The production template source is procedural, not a finite catalog. The census
covers **all 720 layout occurrences generated by seeds 1–30**, with the original
API sampling and candidate preparation RNG consumption. Duplicate geometries
are identified explicitly. It does not claim to enumerate all possible grids.
`baseline/` pins the source and prior 480-run benchmark from the solver checkpoint.
All candidate sets are local; no network timing is involved. Census tests assert
that the full eligible approved English set equals every sampled seed's set.

Commands:

```sh
npm run bench:templates
TEMPLATE_EXPLORE=1 TEMPLATE_BATCHES=55 npx vitest run --config vitest.template-feasibility.config.ts benchmarks/template-feasibility/explore.benchmark.ts
TEMPLATE_DEEP=1 npx vitest run --config vitest.template-feasibility.config.ts benchmarks/template-feasibility/deep.benchmark.ts
npm run bench:templates:controls
APPROVED_BENCH_OUTPUT=template_feasibility_13x13/after npm run bench:approved
python3 scripts/template-feasibility-report.py
```

The exact approved benchmark npm script name is listed in package.json. All
benchmarks should run without another CPU-heavy test/build process alongside.

## Classification

A: zero initial domain. B: initial arc propagation contradiction. C: exhaustive
search contradiction. D: complete solution passed through the unchanged builder
and validator. E: analysis budget expired; **not a proof**.

Census uses the existing instrumented arc solver without optional experimental
propagation, MRV, LCV, Hall, or uniqueness variants. Normal/inverted values are
both available; canonical answers cannot be reused. Budget: 500ms/layout for
analysis only. `slots.csv` and `intersection_graph.csv` enumerate the geometry;
`full-pool.json` defines every initial domain by canonical answer length. Census
initial domain counts are canonical; propagated counts include orientations.

All 720 occurrences are proven impossible (719 C, one B). No initial length
bucket is empty. Thus restricting to a feasible/unknown class in this catalog
leaves no template. Reordering known contradictions cannot repair it.

## Structural finding

A minimum white run of three and maximum black run of two force rows **2 and 10**
and columns **2 and 10** (zero-based) to remain entirely white. At row 2, a black
cell would have either a too-short white run above it or three consecutive
blocks; the same argument applies from each edge. Every 13×13 template therefore
contains at least four crossing 13-letter words, regardless of random seed or
block density.

The 33 approved 13-letter canonical answers admit 608 oriented, distinct-answer
assignments to that frame in isolation. The frame alone is **not** a proof of
impossibility. Its combination with surrounding entries is the measured issue.
All observed families fail; these data cannot establish a causal ranking of
individual lengths by comparing successful and failed templates, since there
are no successful ones in the census. Raw rarity is not the diagnosis.

## Additional layout exploration

`layouts.ts` is a benchmark-only copy of the existing template algorithm with an
adjustable stopping block density. The completed exploration covers 5,500
layouts at 18%, 22%, 26%, and 30% density ceilings. Minimum run three, maximum two
consecutive blocks, white connectivity, and the 30% ceiling remain unchanged.
No solution was found at 100ms/layout. `deep.json` reruns the unique unknown
layouts with a 5-second **offline classification** budget; this is not a runtime
budget increase. `original-family-exploration.json` preserves an earlier,
interrupted exploration using the original 30% generator (1,400 completed
layouts). Replay its completed prefix with `TEMPLATE_DENSITIES=.30
TEMPLATE_BATCHES=14 TEMPLATE_EXPLORATION_OUTPUT=original-family-exploration.json`
in addition to `TEMPLATE_EXPLORE=1`. Unknown outcomes in that earlier prefix are
not counted as proofs.

No newly explored geometry is promoted to production without a solution witness.
Two-letter English layouts are a separate possible experiment: the validator
accepts length two, but production template discovery currently requires three.
That experiment was put to the user explicitly and has not been authorized or
performed in this checkpoint.

## Feasibility ordering controls

All four controls replay frozen checkpoint generator/solver sources with the
same pools, seeds, and runtime budgets:

- A: current production order.
- B: remove templates with complete A/B/C proofs.
- C: prioritize actual feasibility signals: complete solution, unknown, then
  proven-impossible; within a class use deepest consistent assignment fraction,
  propagation survival, and small-domain count; original quality breaks ties.
- D: restrict to the best non-impossible class (empty in this census).

B/C/D use the independently collected full-pool census as an offline oracle.
Their online times **exclude** that census cost, reported separately in summary.
They are controls, not a deployable claim of free classification. B and D
coincide because every layout is already proven impossible. A scored selector
is not retained simply to reorder an all-impossible catalog.

## Narrow runtime changes and regression results

- Separate candidate/template RNG streams for 13×13 English answers only.
  Other configurations keep the original stream consumption. The request draws
  one seed, then passes RNG functions explicitly; no global RNG replacement.
- Bounded cross-request reuse of complete impossibility proofs for that same
  configuration. Keys include exact sorted canonical answer membership,
  direction, size, and geometry. Any answer addition/removal invalidates the
  pool key. Clue/order changes do not change mathematical feasibility. No
  timeout, subset failure, or incomplete branch is cached. Cache is bounded to
  four candidate sets and 1,024 layouts each.

These changes address stability and repeated work, **not** the feasibility of an
impossible layout. They do not by themselves meet the 80% acceptance target.

See `RESULTS.md`, `summary.json`, `experiments.csv`, and `before_after.csv` for measured results. The independent-stream census repeats classification on the new layouts: all 720 occurrences remain proven impossible.
Batch007 remains paused; more generic vocabulary review is not justified by
this experiment. The next step is a template-constraint decision or further
joint layout/word feasibility investigation with the fixed dictionary.
